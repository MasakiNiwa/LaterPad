# LaterPad 仕様書

> 書式をAIに渡すための専用エディタ
>
> **普通に書く。AI に伝わる形でコピーする。**

## 1. コンセプト

LaterPad は Markdown を書くためのエディタではない。人間が直感的に書式付きで文章を書き、
その構造を AI に渡しやすいテキスト形式へ変換してコピーするための専用エディタである。

- 記法（Markdown / XML 等）を意識せず、リッチテキストとして編集する
- 書式を使わなければ、シンプルなテキストエディタとして自然に使える
- 「AI用にコピー」が主要機能。形式は基本的に LaterPad が選ぶ（推奨形式）

### やらないこと

高機能なプロンプト管理ツールは目指さない。機能を追加する前に
「これは AI へ文章を渡すためのエディタとして本当に必要か」を判断する。

- 文字色・フォント変更・複雑な表装飾・ページレイアウト
- タグ、部品管理、プロンプトライブラリ、プロジェクト管理
- Git のようなブランチ／マージ

## 2. 技術構成

| 領域 | 採用技術 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript | 型による保守性 |
| UI | React 19 | エコシステムと Tiptap の公式サポート |
| エディタ | Tiptap v3（ProseMirror） | 構造化された文書モデル（JSON）を持ち、拡張で書式を追加できる |
| デザイン | MUI（Material Design 3 のトークンでテーマ化） | レスポンシブ部品・ダイアログ・ダークモードが揃う |
| ルーティング | React Router（HashRouter） | GitHub Pages でサーバー設定なしに動作 |
| ビルド | Vite | 高速・静的出力 |
| テスト | Vitest | 変換ロジックの単体テスト |
| 公開 | GitHub Actions → GitHub Pages | main へのマージで自動デプロイ |

## 3. アーキテクチャ

```
src/
  core/              エディタ・UI に依存しない中核ロジック
    document.ts      文書構造（ProseMirror JSON 互換の DocNode）
    export/          AI 用コピーの変換器（Exporter）と登録簿
    storage/         保存・一時保存
  editor/            Tiptap 拡張・ツールバー・エディタ固有 UI
  pages/             画面（エディタ／設定／ヘルプ）
  components/        共通 UI
  settings/          ユーザー設定（localStorage）
```

### 3.1 保存形式と出力形式の分離

- **内部（保存）形式**: 文書構造そのもの（ProseMirror JSON 互換の木構造）。Markdown は保存の中心にしない。
- **出力形式**: `Exporter` インターフェースを実装した変換器。`core/export/index.ts` の
  `exporters` に登録するだけで新しい形式を追加できる。
- **推奨形式**: `RECOMMENDED_EXPORTER_ID` が指す形式。ユーザーは通常これを使い、
  LaterPad 側の改善で差し替わる。設定で特定の形式に固定することもできる。

### 3.2 Markdown 変換ルール（現行の推奨形式）

| 要素 | 出力 |
| --- | --- |
| 段落が連続 | 1 改行で連結（Enter で改行した見た目を保つ） |
| 空段落 | 空行（3 行以上の連続改行は 2 行に圧縮） |
| 見出し 1〜3 | `#` 〜 `###`、前後に空行 |
| 太字 / 斜体 / 取り消し線 | `**` / `*` / `~~`（隣接する同一装飾は結合、前後空白は外へ） |
| インラインコード | `` ` ``（中にバッククォートがあれば本数を増やす） |
| リンク | `[text](url)` |
| 箇条書き / 番号付き | `- ` / `1. `（入れ子はマーカー幅でインデント） |
| 引用 | 各行に `> ` |
| コードブロック | フェンス（言語指定対応、中身に応じてフェンス長を調整） |
| 表 | GFM 表。1 行目を見出し行とし、`|` はエスケープ、セル内改行は `<br>` |
| 区切り線 | `---` |

AI が読むことを前提とし、本文中の記号の過剰なエスケープは行わない。
コードブロックには言語を指定でき（ツールバーの「言語」欄）、フェンスに付与される。

### 3.3 AI書式（意味ブロック）

見た目の書式（Markdown で表せるもの）だけでは、文章の各部分が AI にとって何なのかは伝わらない。
LaterPad は「意味ブロック」で文章の役割を明示し、AI用コピー時に役割ごとの XML タグで囲む。
XML タグによる区切りは主要な AI ベンダーがプロンプト構造化の方法として推奨しており、
特に「資料の中の文を指示と取り違える」問題を防げる。

| ブロック | タグ | 用途 |
| --- | --- | --- |
| 指示 | `<instructions>` | AI にしてほしいこと |
| 背景 | `<context>` | 前提・目的・状況 |
| 条件 | `<constraints>` | 守ってほしいルール・制約 |
| 資料 | `<data>` | 処理対象の文章・データ（指示ではない） |
| 出力形式 | `<output_format>` | 回答の形・長さ・書き方 |
| 例 | `<example>` | 入力と出力の見本 |
| メモ | （出力しない） | 自分用のメモ |

- ブロックには任意の名前を付けられ、`<data title="議事録">` のように属性として出力する。
- ブロックの中身は通常の書式（リスト・表・コードなど）で書け、Markdown として出力する。空のブロックは出力しない。
- ブロックの外の本文はそのまま Markdown で出力する（書式を使わなければプレーンな文章になる）。
- 編集画面では役割ごとに色分けし、上部のラベルから種類の変更・名前・解除ができる。
  最後の空行で Enter → ブロックの外へ、先頭で Backspace → その段落をブロックの外へ。
- 保存形式では `aiBlock` ノード（`role`, `label` 属性）として保持する。
- 空のブロックには役割ごとの書き方の例を表示する（CSS 変数 `--ai-hint`）。
- テンプレート（空のブロックの組み合わせ）: 基本の依頼／資料を渡して処理／文章を作ってもらう／相談・質問する。
- 入れ子: ブロック内で「AI書式」を選ぶと入れ子のブロックを作る（種類の変更はブロックのラベルから）。
  出力は入れ子のタグになる。基本は横に並べることを推奨（ヘルプに書き方のコツを記載）。
- ブロックの名前は入力中は文書に反映せず、確定時（フォーカスが外れた時・Enter）に反映する（日本語入力の変換を妨げないため）。
- ブロック操作（ラベルのメニュー）: 上へ／下へ移動、中身を選択、中身をコピー（中身を AI書式で）、中身をすべて削除、解除、削除。
- ドラッグ: ラベル左のつまみを押したまま上下に動かす（ポインターイベントで実装し、マウス・タッチ共通）。
  移動先は元と同じ親の中に限定し、落とす位置を線で示す。画面の上下端では自動スクロールする。
- `Ctrl/⌘+A`: カーソルのある意味ブロックの中身だけを選択。もう一度で外側のブロック、最後に文書全体。
- 重要度（必須／推奨）: 文字に付ける印（`priority` マーク、`level` 属性）。選択がなければカーソルのある行（段落内の改行区切り）に付ける。
  編集画面ではラベル付きの下線、出力では該当箇所の先頭に【必須】【推奨】を付ける（全形式共通）。
- 今後の候補: 変数（差し込み）、自作テンプレート。

### 3.4 リストの拡張

- チェックリスト（`taskList` / `taskItem`、`checked` 属性）。Markdown は `- [ ]` / `- [x]`、プレーンテキストは ☐ / ☑。
- 項目内の改行: `Shift+Enter` またはリストメニューの「項目内で改行」。出力では続きの行として字下げする。
- 設定「リストの項目内で改行する」: Enter で項目内改行、空の行でもう一度 Enter で新しい項目。

### 3.5 出力形式一覧

| ID | 名前 | 内容 | 向いている用途 |
| --- | --- | --- | --- |
| `laterpad-ai` | AI書式（**推奨**） | 意味ブロックを XML タグ、それ以外を Markdown | ほとんどの場合 |
| `markdown` | Markdown | 3.2 のルール。意味ブロックは「**【指示】**」のような見出し行 | タグを使いたくない場合 |
| `markdown-xml` | Markdown + XML タグ | 全体を `<document title="タイトル">`、見出しごとの範囲を入れ子の `<section title="見出し">` で囲み、本文は Markdown | 長文、指示と資料が混在する文書 |
| `plain` | プレーンテキスト | 記法なし。リストは `・` / `1.`、表はタブ区切り | 書式が不要な場合 |

推奨形式は AI書式（v0.8.0 で Markdown から変更）。意味ブロックを使わない文書では Markdown と同じ出力になる。
Markdown + XML タグはタイトル（文書名）も出力に含め、意味ブロックも同じタグで出力する。

## 4. 画面

| 画面 | パス | 内容 |
| --- | --- | --- |
| エディタ | `#/` | 書式ツールバー、本文、AI用にコピー、プレビュー |
| 設定 | `#/settings` | テーマ、文字サイズ（12〜24px）・行間（1.2〜2.2）・余白を狭くする、コピー形式、起動時の動作、コピー時の履歴記録 |
| ヘルプ | `#/help` | 使い方、ショートカット、バージョン情報、GitHub リンク |

- 上部バー 1 段目: ロゴ・文書タイトル欄（ファイル名に使用、保存状態の色付き点）・設定・ヘルプ。
- 上部バー 2 段目（アイコン＋ラベルの操作ボタン）: 新規・開く ｜ 保存・別名保存 ｜ 戻す・進む ｜ 検索・履歴・プレビュー ｜ **AI用にコピー**（唯一のコピーボタン、塗りつぶしで強調）。
  スマホではプレビューを操作バーから省き、下部ステータスバーの「プレビュー」とコピー後のお知らせの「内容を見る」から確認する。
  置換は検索バーから、「今の状態を記録」は履歴パネルから使う。スマホでは均等幅で 1 行に収める。
- 下部ステータスバー: ファイル名・保存状態・文字数・行数。
- ソフトウェアキーボード表示時（Visual Viewport API で検知）:
  上部バーは見えている領域の上端に固定し、1 段目（タイトル行）を省いて操作ボタンと書式ツールバーを残す。
  ステータスバーはキーボードの直上に移動する。
- スマホでは、保存・開く・履歴などのボタンを押すと本文の入力を終えてキーボードを閉じる（戻す・進むは入力状態を保つ）。
  起動時・文書の読み込み時もキーボードを自動で開かない。
- 起動時は空の文書で始める。前回の内容は起動直後の「復元」から戻せる。設定「前回の内容を開く」で続きから始めることもできる。
- 検索・置換バー（`Ctrl/⌘+F` / `Ctrl/⌘+H`）: 一致箇所のハイライトと件数、前後移動、大文字小文字の区別、置換・すべて置換。
- 表の中にいるときは、書式ツールバーの下に「行を足す・列を足す・行を削除・列を削除」のクイック操作列を表示。
- 書式ツールバー: 機能ごとのグループボタン。PC では押すとメニュー、スマホでは押すと「アクション列」
  （そのグループの機能を 1 タップで使えるボタン列。開いたままにでき、もう一度押すと閉じる）を表示する。
- 圧縮表示（設定「ボタンの文字を省略する」）: 操作ボタン・ツールバー・アクション列をアイコンだけにする。
  名前はツールチップと読み上げで分かる。スマホでも余裕ができるためプレビューボタンを表示する。

  | グループ | 機能 |
  | --- | --- |
  | 段落（現在のスタイル名を表示） | 本文・見出し 1〜3・引用・コードブロック |
  | 文字 | 太字・斜体・取り消し線・インラインコード・書式クリア |
  | リスト | 箇条書き・番号付き・字下げ／戻す |
  | 挿入 | リンク・表（マス目で行数×列数を選択）・区切り線 |
  | 表（表の中にいるときだけ表示） | 行・列の挿入（上下左右）と削除、セルの結合／解除、見出し行・見出し列の切り替え、表の削除 |

- PC: 本文は最大幅 900px。スマホ: 書式ツールバーは横スクロール。
- 結合セルは出力時に格子へ展開し、結合された残りのマスは空にする（列ずれ防止）。
- 設定・ヘルプ・（今後の）リビジョン履歴は必要なときだけ開く。

## 5. ファイル形式

「1 文書 = 1 保存ファイル」。拡張子 `.laterpad`（中身は JSON）。
保存時の MIME タイプは `application/x-laterpad`（`application/json` だとブラウザが `.json` を付け足すため）。
以前のバージョンで保存された `*.laterpad.json` もそのまま開ける。

```jsonc
{
  "format": "laterpad",
  "formatVersion": 1,
  "id": "uuid",
  "title": "文書タイトル",
  "createdAt": "ISO8601",
  "updatedAt": "ISO8601",
  "content": { "type": "doc", "content": [ /* DocNode */ ] },
  "revisions": [
    {
      "id": "uuid",
      "createdAt": "ISO8601",
      "reason": "copy | save | manual | restore",
      "content": { /* DocNode */ }
    }
  ]
}
```

- `formatVersion` で将来のマイグレーションに対応する。新しいバージョンのファイルは読み込みを拒否する。
- 未知のフィールドは読み込み時に保持する（前方互換）。壊れたリビジョンは読み込み時に除外する。

### 5.1 保存・読込

| 操作 | 内容 |
| --- | --- |
| 新規作成 | 空の文書を作る。未保存の変更があれば確認する |
| 開く（`Ctrl/⌘+O`、ドラッグ＆ドロップ） | `.laterpad` を読み込む。未保存の変更があれば確認する |
| 保存（`Ctrl/⌘+S`） | 開いたファイルへ上書き。初回は保存先を選ぶ |
| 名前を付けて保存 | 常に保存先を選ぶ |

- File System Access API 対応環境（PC の Chrome / Edge）では同じファイルへ上書き保存する。
  非対応環境（Safari / Firefox / スマホ）では保存はダウンロード、読込はファイル選択になる。
- タイトルはファイル名の初期値に使う（OS で使えない文字は `_` に置換）。タイトル未入力時は `無題.laterpad`。
- 編集中の文書（リビジョンを含む）は、ファイル保存とは別にブラウザ内（localStorage）へ自動で一時保存し、
  リロードしても失われない。ファイルハンドルはメモリ上のみで保持するため、リロード後の保存は保存先の選択からになる。
- 別の文書を読み込むとエディタを作り直し、Undo 履歴もリセットする。

## 6. リビジョン管理

- 履歴パネル（右側のドロワー、スマホでは全画面）で過去版一覧・閲覧・差分表示・復元・削除
- 自動作成のタイミング:
  - **AI用にコピーした時点**＝プロンプトの形が固まったタイミング（設定でオフにできる）
  - 復元の直前（復元自体を取り消せるように）
  - ファイル保存時には記録しない（本文はファイルに保存されるため。v0.8.0 で変更）
- 「今の状態を記録」で手動作成（手動は同じ内容でも常に記録）
- 直前のリビジョンと内容・タイトルが同じ場合は自動作成しない（何度コピーしても増えない）
- 1 文書あたり最大 200 件。超えた分は古いものから削除
- 差分は現在のコピー形式のテキスト同士を行単位で比較する（「現在と比較」「前の版と比較」）
- 「この版をコピー」で過去版の内容を AI 用にコピーできる
- 復元はエディタの内容差し替えとして行い、Undo（`Ctrl/⌘+Z`）でも取り消せる
